# Centralized Dashboard (app2.py & frontend.html)

## Overview
The centralized dashboard provides a user-friendly interface for monitoring and visualizing alerts generated by the HIDS and NIDS components. It includes a backend API (`app2.py`) for handling alert data and a frontend (`frontend.html` and `app.js`) for displaying real-time alerts and metrics.

## Features
- **Real-time Alerts**: Displays alerts generated by HIDS and NIDS.
- **Severity-based Visualization**: Categorizes alerts by severity (Low, Medium, High).
- **Metrics Monitoring**: Tracks system throughput and resource usage.
- **User-friendly Interface**: Intuitive and accessible design for junior analysts.

## Requirements
- Python 3.8+
- Dependencies:
  - `flask`
  - `flask-cors`
  - `colorama`
  - `requests`

Install all required packages using:
```bash
pip install -r requirements.txt
```

## Setup Instructions

### Step 1: Configure the Backend
1. Ensure `app2.py` is configured with the necessary logging settings.
2. The default endpoint is set to `http://127.0.0.1:5000`. Update the configuration if needed.

### Step 2: Run the Backend
Start the backend server using the following command:
```bash
python app2.py
```
The server will listen on `http://127.0.0.1:5000` by default.

### Step 3: Launch the Frontend
1. Open `frontend.html` in a web browser.
2. Ensure the backend (`app2.py`) is running and accessible from the browser.

## Usage
- **Access the Dashboard**: Navigate to `http://127.0.0.1:5000` in your web browser.
- **Monitor Alerts**: View alerts categorized by severity with detailed information about each event.
- **Visualize Metrics**: Analyze alert distribution and system performance.

## File Structure
- `app2.py`: Backend script for managing alerts and API endpoints.
- `frontend.html`: HTML file for the dashboard interface.
- `app.js`: JavaScript file for frontend interactivity.

## Integration
- Receives alerts from:
  - **HIDS Manager**
  - **NIDS**
- Serves as the primary interface for analysts to monitor and respond to alerts.

## Example Workflow
1. Start the backend server (`app2.py`).
2. Open the dashboard frontend (`frontend.html`) in a browser.
3. Simulate attacks using provided tools or generate alerts from HIDS and NIDS.
4. Monitor the dashboard for real-time updates.

## Notes
- The backend uses Flask and supports CORS to enable communication with the frontend.
- Logs are stored in `app.log` for backend activities.
- The dashboard requires an active backend to fetch and display data.
